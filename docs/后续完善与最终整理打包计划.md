# 投刊机器人后续完善与最终整理打包计划

## 一、当前状态

项目已经完成 Tauri + Rust + Web 前端的桌面架构，数据位于：

`D:\投刊机器人\data`

当前已经具备或正在使用：

- 独立桌面窗口，不依赖浏览器
- SQLite 本地数据库
- 期刊雷达、收藏、投稿记录、模板、资源导入
- OpenRouter / xFastAPI 接口
- 本地规则推荐、RAG、向量相似度
- FTS5/BM25 关键词检索
- JIF 分区筛选
- Q3/Q4 联网补充的本地分区核验
- 个人经验修正推荐
- 数据备份与数据库迁移机制
- 小规模期刊真实数据补全试验

当前最近的测试程序：

`D:\投刊机器人\投刊机器人-Q分区联网过滤测试.exe`

注意：该文件是上一轮测试版，不能直接视为最终版。刚刚新增的期刊信息补全代码需要重新编译后才会进入最终测试程序。

## 二、必须保留的原则

1. 旧版 `投刊助手源码` 保留不动，作为功能蓝图和回退版本。
2. 旧版任何功能、提示、边界行为都不能因为重构而删除。
3. 不使用服务器也能完整运行本地核心功能。
4. 爬不到的真实数据保持为空，不得猜测或编造。
5. 自动抓取不得覆盖用户手动填写的内容。
6. 影响因子、JIF、中科院分区、收录情况必须记录来源和日期。
7. RAG 只能辅助判断匹配度，不能凭空替代权威期刊数据。
8. ABCD 是“系统评估等级”，不能冒充官方等级。
9. 在用户确认测试通过前，不得正式打包。
10. 删除旧测试程序前必须完成最终备份，并确认最终程序能启动和运行。

## 三、下一步工作顺序

### 阶段 1：扩大真实数据小规模验证

先选择计算机方向的少量期刊进行验证，建议先处理 10 至 30 本，不直接处理全部期刊。

优先补充：

- ISSN / eISSN
- 期刊官网
- 官方 Aims & Scope
- 官方投稿指南
- Crossref 近期文章标题
- 出版商信息
- 数据来源网址
- 抓取时间
- 字段可信状态

数据来源顺序：

1. 期刊官网
2. 出版商官方页面
3. Crossref 等公开元数据服务
4. 用户手动上传或补充的数据

影响因子、JIF 分区、中科院分区、CCF 等字段，只能使用可靠数据源或用户提供的真实数据。无法确认时保持为空。

### 阶段 2：补全流程加入界面

在“期刊雷达”或“设置与诊断”中加入：

- 选择少量期刊进行补全
- 预览可补充字段
- 显示每个字段的来源和抓取时间
- 只写入空字段
- 跳过不可靠字段
- 查看失败原因
- 批准写入
- 取消本次补全

界面必须显示醒目提示：

- 蓝色：普通说明
- 黄色：重要说明
- 中国红：风险或失败提示
- 紫色 / 粉红色：结果或状态强调

不得使用与背景接近的颜色。

### 阶段 3：RAG 增量更新

补全成功后：

1. 自动标记对应期刊索引过期。
2. 只重建发生变化的期刊，不默认重建全部期刊。
3. 生成 profile、scope、articles、guidelines、experience 类型 chunk。
4. 重新计算向量 embedding。
5. 更新 FTS5/BM25 内容。
6. 在界面显示索引状态和更新时间。

如果抓取失败，不能影响旧的 RAG 数据和本地推荐。

### 阶段 4：恢复 ABCD 等级和性价比分

恢复旧版中的：

- A/B/C/D 等级
- 精品难发等文字标签
- 性价比分
- 影响因子排序
- WOS 论文数排序
- 收藏筛选和导出字段

评分必须区分：

#### 基础数据分

根据真实字段计算：

- JIF 分区
- 中科院分区
- 影响因子
- SCI/SCIE、EI、SSCI 等收录
- CCF 等级
- Top / OA
- WOS 论文数

#### RAG 匹配分

根据论文信息与期刊以下内容的语义相似度计算：

- 官方 Scope
- 近期文章主题
- 投稿指南
- 期刊画像

#### 个人经验修正分

根据用户填写的：

- 易 / 中 / 难 / 极难
- 正常推荐 / 少推荐 / 不推荐
- 适合保底 / 适合冲刺
- 版面费
- 审稿周期
- 拒稿原因
- 推荐原因
- 不推荐原因

最终分数：

`最终分 = 基础数据分 + RAG匹配分 + 个人经验修正分`

没有个人经验时，也必须能正常评分。个人经验只是修正项，不是必填项。

数据不足时显示：

`当前评分依据不完整，仅供参考`

### 阶段 5：全面回归测试

必须测试：

- 只输入题目也能推荐
- 信息不足时有醒目提示
- 无 API Key 时本地推荐仍可用
- AI 失败时本地规则兜底
- xFastAPI 模型可选且错误可读
- OpenRouter 能正常选择模型
- Q1、Q2、Q3、Q4 可以单独或组合筛选
- 联网补充会遵守分区条件
- 重复点击推荐会换新结果
- 期刊雷达支持分页
- 模板支持搜索、分页、上传和拖拽
- 资源支持附件上传和手动填写期刊名
- 个人经验和期刊信息可以编辑
- 修改后 RAG 索引会更新
- 删除、恢复、导入、备份都有提示
- 旧版数据库和附件迁移不丢数据

### 阶段 6：代码和目录整理

最终建议整理为：

```text
D:\投刊机器人
├─ code
│  ├─ app
│  ├─ frontend
│  └─ crates
├─ data
│  ├─ db
│  ├─ raw_resources

│  ├─ templates

```

整理时需要同步检查 Tauri、Cargo、前端构建路径，不能只移动文件夹后直接运行。

## 四、清理和打包规则

### 可以清理的内容

- 旧的测试 exe
- 重复的临时 exe
- 临时日志
- 过期构建输出
- 不再使用的临时脚本

### 暂时不能删除的内容

- 旧版 `投刊助手源码`
- `D:\投刊机器人\data`
- 数据库、附件、模板、备份
- 当前源代码
- 最后一个可以启动的测试程序
- `target` 和 `frontend\node_modules`

`target` 和 `node_modules` 可以在最终压缩发布包中排除，但如果以后还要继续开发，建议保留在开发目录。

## 五、最终打包前的检查

只有以下条件全部满足后，才能打包：

1. 用户已经测试功能并确认没有阻塞问题。
2. 最新源代码可以编译。
3. 全部核心测试通过。
4. 新版程序可以双击启动。
5. 数据目录不会被安装程序覆盖。
6. API 配置、附件、模板、备份可以保留。
7. 数据库可以自动迁移。
8. 最终备份已经生成。
9. 旧测试 exe 已经确认不再需要。
10. 用户明确说“开始打包”。

正式发布文件建议命名为：

`D:\投刊机器人\release\投刊机器人.exe`

正式版生成后，再删除其他测试 exe。删除前保留一份最终备份和一份旧版回退程序。

## 六、给后续开发者的明确要求

- 不要重新编写已经正常工作的旧功能。
- 修改前先阅读旧版和新版相关模块。
- 不要用假数据填充期刊字段。
- 不要把 Crossref 论文链接当成期刊官网。
- 不要让 AI 凭空生成期刊信息。
- 不要覆盖个人备注和经验。
- 不要把所有代码和数据混在一个目录。
- 不要在用户确认前打包或删除旧文件。
- 每完成一个阶段都要运行编译、测试和冒烟检查。
