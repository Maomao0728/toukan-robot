# 投刊机器人项目目录整理说明

## 当前目录职责

```text
D:\投刊机器人
├─ app                 Tauri 桌面壳代码
├─ frontend            Web 前端代码
├─ crates              Rust 核心业务代码
├─ data                用户数据，不能随意删除
├─ docs                文档和交接说明
├─ installer           后续安装包配置
├─ release             当前可测试程序和后续正式发布文件
├─ target              Rust 构建缓存，可重新生成
├─ Cargo.toml          Rust workspace 配置
├─ Cargo.lock          Rust 依赖锁定文件
├─ README.md           项目说明
└─ 投刊机器人-学科过滤修复测试版.exe  当前根目录保留的最新测试版
```

## 绝对不能删除

- `data\db`
- `data\attachments`
- `data\templates`
- `data\raw_resources`
- `data\backups`
- `app`
- `frontend`
- `crates`
- `Cargo.toml`
- `Cargo.lock`

## 可以重新生成但不建议随手删

- `target`
- `frontend\node_modules`
- `frontend\dist`

这些目录占空间，但用于继续开发和快速构建。正式压缩给别人使用时可以排除；如果后续还要开发，保留更省时间。

## 后续建议

暂时不要把 `app`、`frontend`、`crates` 直接移动进 `code` 文件夹。这样会影响 Cargo workspace、Tauri 配置、前端路径和构建脚本。若确实要重构为 `code` 目录，需要同步修改配置并重新完成编译测试。

正式打包前建议：

1. 用户确认 `release\投刊机器人-当前测试版.exe` 功能通过。
2. 运行前端构建。
3. 运行 Rust 测试。
4. 运行 Tauri release build。
5. 把正式程序输出到 `release`。
6. 不把 `target`、`node_modules`、旧测试 exe 打进发布压缩包。
